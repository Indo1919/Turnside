# Turnside integrations

Turnside starts with conversation, returns selectable place cards, and builds a suggested day around those exact selections. The editorial demo works without API keys or AI credits. New York is the default, with demo itineraries for Tokyo and Paris. No reservations, payments or automatic purchases are made.

Copy `.env.example` to `.env.local` to configure providers. Gemini and Google server keys must stay private and must never use a `VITE_*` environment variable. Only `GOOGLE_MAPS_BROWSER_KEY` is intentionally returned to the browser; restrict it to the app origin and intended browser APIs. Provider status `configured` means a key is present, not that the connection has been verified.

## Providers and limits

| Feature                           | Demo                                                                       | Live setup                                                                                                                                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Conversation and recommendations  | Guided conversation with labeled editorial cards and venue sources         | `GEMINI_API_KEY`, optional `GEMINI_MODEL` (default `gemini-3.8-flash`). Interactions API uses Google Maps and Google Search grounding.                                                                             |
| Place identity and details        | Editorial coordinates and official venue links                             | Private `GOOGLE_PLACES_API_KEY` or `GOOGLE_MAPS_SERVER_KEY` with Places API (New) enabled. Real provider location, rating, review count, hours, links and attribution. Missing fields remain absent.               |
| Maps                              | Local Stadia/OSM tiles and separate consumer Google Maps viewing           | Public `GOOGLE_MAPS_BROWSER_KEY` for Maps JavaScript; optional public `pk.*` `MAPBOX_ACCESS_TOKEN`.                                                                                                                |
| Street routes                     | Explicit straight-line preview                                             | Private `GOOGLE_ROUTES_API_KEY` or `GOOGLE_MAPS_SERVER_KEY` with Routes API enabled. Google geometry is returned only for a Google map; optional Mapbox Directions otherwise.                                      |
| Live voice conversation           | No simulated substitute                                                    | `GEMINI_API_KEY`, `GEMINI_LIVE_ENABLED=true`. Real `gemini-3.8-live`, interruptible speech, transcriptions and discovery/planning tools. A constrained ephemeral token goes to the browser, never the private key. |
| Recorded voice and spoken replies | Unavailable without a key                                                  | Real `gemini-3.8-flash` audio understanding and `gemini-3.8-flash-tts` speech through Interactions API. `GEMINI_VOICE_ENABLED=true`; optional `GEMINI_TTS_VOICE=Kore`.                                             |
| NYC area density                  | Official NYC public data when reachable; labeled editorial fallback        | DOHMH restaurant inspections and DCP Facilities via NYC Open Data. Inventory density across six editorial geographic windows, not live popularity or crowds.                                                       |
| Neighborhood discovery            | First-party-source editorial picks, photos labeled venue or representative | Optional grounded conversation and Google venue lookup. No TikTok global search/metrics, live crowd feed or Google Popular Times API.                                                                              |
| Weather                           | Labeled sample when unreachable                                            | Open-Meteo, no key for this prototype; 10-minute memory cache. Forecast, not a severe-weather alert system.                                                                                                        |
| Booking                           | Official venue handoff, explicitly `NOT BOOKED`                            | No booking/payment API or ticket inventory is integrated. Complete purchase with the provider.                                                                                                                     |
| Calendar and sharing              | .ics export, Google Calendar links, text/browser share                     | No calendar OAuth/account sync. Tentative itinerary reminders use the destination timezone. Nothing is sent automatically.                                                                                         |

`AI_MODE=demo` is the server default. The UI enables live typed conversation when a Gemini key is present; Settings can select Demo. `forceDemo:false` explicitly opts a planning/chat/discovery request into Gemini when a real key is configured; `forceDemo:true` keeps it credit-free. User-initiated voice requests use real provider credits even in demo itinerary mode. No browser speech or fake fallback claims a real connection.

The private `GOOGLE_MAPS_SERVER_KEY` alias is compatible with the teammate project. Separate Places/Routes keys take precedence; legacy `GOOGLE_MAPS_API_KEY` is also server-only. Google Maps and Gemini billing and API access must be enabled for the chosen features. Requesting Places ratings/hours uses Google's Enterprise field tier. Grounding may execute multiple billable searches; do not assume one prompt means one search. Check current [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing) and [Google Maps pricing](https://developers.google.com/maps/billing-and-pricing/pricing). Review Open-Meteo licensing before commercial deployment.

## API contracts

- `GET /api/config` or `/api/integrations`: public browser keys/tokens, key-presence flags, default mode/model and provider setup/status. Private keys never appear.
- `POST /api/gemini/chat`: `{ message, city?, currentItinerary?, activeStop?, userLocation?, conversationHistory?:{sender,text}[], forceDemo? }`. An itinerary is optional, so conversation can start before planning.
- `POST /api/discover`: `{ query, city?, areaId?, category?, userLocation?:[longitude,latitude], conversationHistory?, forceDemo? }`.
- Both conversation endpoints return `{ success, reply, recommendations, sources, source:'demo'|'gemini', notice?, fallback?, mapsWidgetContextToken?, searchSuggestionsHtml? }`. Shared types are in `src/recommendationTypes.ts`. Google cards require a returned Maps citation/ID. Model-invented IDs, coordinates, ratings, review counts and availability are discarded. With no Places key, cited cards remain link-only and cannot be scheduled.
- `POST /api/gemini/plan`: `{ destination?, prompt?, vibe?, durationDays?:1..3, pacing?:'relaxed'|'balanced'|'fast', travelerNote?, startDate?:'YYYY-MM-DD', preferredPlaceIds?:string[], forceDemo? }` → `{ success, data:TripPlan, source, notice?, fallback? }`. New York/NYC/NY/Manhattan are aliases. Selected IDs resolve against an approved catalog or the bounded, 20-minute in-memory recommendation store. Forged, stale, wrong-city, or unlocated selections return 409. Selected-place scheduling does not spend a second Gemini request. Legacy direct live planning uses approved catalog IDs in demo cities; non-catalog direct plans are explicitly unverified suggestions.
- `GET /api/discover/area?areaId=soho&category=all`: NYC editorial neighborhood cards with first-party venue evidence. Valid categories: all/food/culture/outdoors. Unknown areas/categories return 400.
- `POST /api/live/session`: `{ city?, contextSummary? }` → `{ success, token, model:'gemini-3.8-live', apiVersion:'v1beta', expiresAt, newSessionExpiresAt, liveConfig }`. Official `auth_tokens` service; single use, 30-minute expiry, 60-second start window. Model, instructions, tools and transcription settings are locked; client resumption handles are allowed. Tools are `discover_places` and `create_plan`. Missing key returns 503; six token requests/minute/caller. `token-issued` does not imply a successful voice WebSocket.
- `POST /api/voice/transcribe`: `{ audioBase64, mimeType, durationSeconds? }` → `{ success, transcript, source:'gemini', model:'gemini-3.8-flash' }`. WebM/Ogg/MP4/M4A; 4MB decoded and 60-second limits. Invalid recordings cause no provider request.
- `POST /api/voice/speak` (legacy `/api/gemini/tts`): `{ text:1..3000 chars, voiceName? }` → `{ success, audioBase64, mimeType:'audio/wav', model:'gemini-3.8-flash-tts', source:'gemini' }`. Uses official speech metadata/audio response schema. Declared PCM is wrapped as WAV. No fake or browser fallback.
- `POST /api/places/details`: `{ name, city }` → `{ success, place:{ name,id?,address?,coordinates?,rating?,reviewCount?,openingHours?,googleMapsUri?,websiteUri?,attributions,source:'google-places',attribution:'Google Maps',fetchedAt }, notice }`. Text Search New with bounded fields, no persisted cache. Missing key: 503.
- `POST /api/route`: `{ coordinates:[longitude,latitude][] (2..25), mode?:'walking'|'cycling'|'driving', mapProvider?:'google'|'osm'|'mapbox', mapboxToken?:public_pk_token }` → `{ coordinates, distanceMeters, durationMinutes, source:'google-routes'|'mapbox'|'preview', notice, attribution? }`. Invalid or unavailable street geometry becomes a labeled preview. Google geometry must be shown only on a Google map.
- `POST /api/gemini/book`: `{ stopTitle, city, slotTime?, partySize?:1..20 }` → provider handoff with `status:'handoff'`, `reservationCode:'NOT BOOKED'`.
- `POST /api/gemini/replan`: `{ currentStops, delayMinutes?:0..180 }` → actual adjusted times, summary and conflicts. Completed/skipped stops and confirmed reservation times stay fixed.
- `GET /api/weather?lat=40.7&lng=-74`: real Open-Meteo forecast or explicitly labeled sample.
- `GET /api/heatmap?city=New%20York`: public inventory counts/density/source metadata; bounded Socrata queries and a 20-minute memory cache. Outside NYC returns unavailable coverage. The legacy telemetry endpoints remain explicitly editorial/session samples.

Calendar helpers accept `createEventPayloadFromStop(stop,date,dayIndex,timeZone?)` and canonical `trip.timeZone` with legacy `trip.timezone` compatibility. Exports respect trip dates, daylight-saving offsets, text escaping, line folding and tentative reminders.

## Source presentation

Google place content is not persisted to disk or browser local storage. Display Google Maps source names and their returned URLs immediately next to the supported generated content, accessible in one interaction. Preserve the exact Google Maps text and third-party attribution. Ratings/review counts are provider signals, not proof of crowds, trending, or authentic reviews. The Google Search entry-point HTML is passed through only from the provider and must be rendered in a sandboxed frame, not injected as page markup. Route/Places content appears with the appropriate Google map.

## Verification and reuse

Run `npm run lint`, `npm test`, and `npm run build`. Integration tests invoke actual Express handlers without a network listener by default; `TEST_HTTP=1` runs the same checks over localhost when supported. Fixtures verify Maps/Search schemas, authoritative Places resolution, exact selected identities, secret handling, grounded/invented data separation, Routes geometry and fallback, ephemeral-token restrictions, voice/WAV handling, calendar timezone/escaping, weather, demo schedules and honest provider handoffs. They do not prove a real account connection. Real account keys were unavailable during this implementation, so Gemini/Places/Routes/Live connectivity remains unverified.

The supplied Sidequest project was reviewed as code, and its grounded-recommendation → authoritative Places → routing architecture and constrained Live token approach informed this integration. Its Hono, database and booking-worker stack was not imported. Existing weather, calendar and Gemini TTS remain compatible. No new backend runtime dependency was added. This local prototype has no user-account authentication for public hosting.

The Live client is isolated in `src/live` and has ten automated transport/audio/lifecycle checks. All 43 project checks pass. Browser verification covers the interactive sample and responsive UI, not private live accounts.
